# M5 — Privacy and security report

Status: **complete for the implemented scope** (2026-11-17). Device-permission
prompts and a per-site cookie inspector remain deferred and are documented.

## Delivered

### Private browsing (verified)
- Cmd+Shift+N opens a private window (`browser_app::open_browser_window(cx, true)`).
- One non-persistent `WKWebsiteDataStore` per private window, shared by its tabs
  through the opaque `PrivateDataStore` engine API (ADR-0007).
- Private windows record no history and are excluded from session persistence.
- Tab strip shows a "Private" badge; window title is suffixed "(Private)".
- New-tab recents and palette history are suppressed in private windows.

`m5-probe` (one normal + two private windows, same fixture server):
```
private_flag              private windows flagged, normal not
store_isolation           private page saw no cookie from the normal store
private_tab_sharing       two tabs in one private window shared its cookie
private_window_isolation  second private window saw no cookie from the first
session_excludes_private  private marker absent from session.json
history_excludes_private  2 normal visits recorded, no private marker
```

### Cookie and site-data controls
- Clear cookies only (new): fetched through `WKHTTPCookieStore`, deleted one by
  one, completion reported as `CookiesCleared`.
- Clear all site data (cookies, caches, local/session storage, IndexedDB,
  service workers) via `WKWebsiteDataStore.removeDataOfTypes:modifiedSince:`.
- Clear history.
- All three are exposed in Settings → Privacy.

Verified selectivity in `m3-probe`: after setting cookie + localStorage and
clearing cookies only, the reloaded fixture reports `storage-clear-set`
(cookie gone, localStorage kept); after clearing all site data it reports
`storage-clear-clear`.

### Navigation and popup policy
- External schemes (`mailto:`, `tel:`, app schemes) are cancelled in WebKit and
  handed to `NSWorkspace`; `javascript:` from the address bar is treated as a
  search query.
- Popups/new windows always become browser-owned tabs and are rate-limited by
  `browser_security::PopupPolicy` (5 per 3 seconds, unit-tested).

### Downloads safety
- Filename sanitisation and directory confinement (M3, unit-tested); no
  auto-open; OS quarantine applies.

### HTTPS visibility
- Address bar shows a lock for HTTPS and a red "Not secure" label for HTTP.
`m1-probe` asserts both states.

### Documentation
- `SECURITY.md` states the trust boundaries, guarantees and explicit
  non-guarantees (no Chromium-grade site isolation, no permission prompts yet,
  no bundle sandboxing yet).
- ADR-0007 (private browsing), ADR-0008 (deny-by-default device permissions).

## Deferred (documented, not hidden)

- **Camera/microphone prompts**: denied by default. Enabling them requires an
  app bundle with `NSCameraUsageDescription`/`NSMicrophoneUsageDescription`, a
  GPUI permission sheet and remembered per-origin decisions. Scheduled with M6
  packaging (ADR-0008).
- **Location, notifications, clipboard-read**: not exposed; pages requesting
  them fail closed.
- **Per-site cookie inspector**: only bulk clear-cookie/site-data actions exist.
- **Dangerous download warnings**: files are not auto-opened, but there is no
  executable-type warning UI.

## Quality gates

`fmt`, `check`, `clippy -D warnings`, `test` (23 test binaries; 43 core, 18
storage, 6 security, plus fixtures/favicons) and all probes M0–M5 pass.
